Critical Issues

フロントエンド課題分析

🏗️ 単一ファイル肥大化

240KB / 4,602行のHTMLファイルにCSS・JS・テンプレートがすべて内包。保守性・テスト性が極めて低い。

// 現状: innerHTML による巨大な文字列連結 kpiEl.innerHTML = '<div class="detail-card"><h3>' + '総チケット</h3>' + '<div style="font-size:1.8rem">' + esc(total) + '件</div>'

🔀 状態管理の欠如

グローバルな state オブジェクトを直接操作。変更検知なし、再描画はフル再レンダリング。

  • localStorage に全 state を JSON 保存
  • API データとローカルデータの二重管理
  • showView() 呼出しごとに DOM 全体を再構築
  • 画面遷移時に scroll 位置がリセット

🎨 CSS 設計の問題

約1,300行のインラインCSS。ダークモードはセレクタの羅列で管理。

  • CSS変数の不使用（色値がハードコード）
  • dark-mode で50以上のセレクタを上書き
  • レスポンシブ対応が不十分
  • アニメーション・トランジションが最小限

♿ アクセシビリティ

WAI-ARIA 属性がほぼ未使用。キーボードナビゲーション非対応。

  • role / aria-label / aria-live 未設定
  • 絵文字をアイコン代わりに使用（スクリーンリーダー問題）
  • フォーカス管理なし（モーダル含む）
  • カラーコントラスト未検証
Backend

バックエンド課題分析

✅ 優れている設計

  • Router → Service → ORM の3層分離
  • Pydantic v2 による入出力バリデーション
  • 監査ログが全CRUDに組み込み済み
  • SLA計算が営業日・祝日を考慮
  • チケット番号の自動採番（INC-YYYY-NNNN）
  • 124件のユニットテスト

⚡ 改善が必要な領域

  • エラーレスポンスのフォーマットが不統一
  • ページネーションが skip/limit 方式のみ
  • N+1 クエリ問題（relationship の lazy load）
  • Rate Limiting 未実装
  • バリデーションエラーの日本語化未対応
  • CORS 設定が allow_methods=["*"]

🔐 セキュリティ懸念

  • JWT の secret_key が .env 依存（デフォルト値リスク）
  • Refresh Token 未実装（8時間固定）
  • ログイン試行回数制限なし
  • CSRF 対策が未実装
  • ファイルアップロードのバリデーション不足

📊 テストカバレッジ

124テストは良い出発点だが、以下が不足：

  • E2Eテスト（13シナリオのみ）
  • エッジケースのバリデーションテスト
  • 並行処理・レースコンディション
  • パフォーマンス / 負荷テスト

Best Practice #3

状態管理 & API統合

現状の問題

  • グローバル state を直接 mutate
  • API データとローカルサンプルデータが混在
  • 各ビューで loadXxxData() を個別実装
  • エラー状態の表示が不統一
  • ローディング状態の UX が未整備

推奨パターン

  • TanStack Query でサーバー状態を一元管理
  • Zustand / Jotai で UI ローカル状態を管理
  • API クライアントを自動生成（openapi-ts）
  • Optimistic Update でUXを向上
  • エラーバウンダリで統一的なエラー表示

推奨データフロー

Component (View Layer)
useQuery / useMutation で宣言的にデータ取得
↕
TanStack Query (Cache Layer)
自動キャッシュ / 再取得 / Optimistic Update
↕
API Client (Generated)
OpenAPI スキーマから TypeScript 型 & クライアント自動生成
↕
FastAPI Backend
Pydantic スキーマ → OpenAPI 自動出力

Best Practice #5

デザインシステム構築

現状のハードコードされたCSS値を、体系的なデザイントークンとコンポーネントライブラリに移行。

カラートークン定義

/* tokens.css — デザイントークン */ :root { /* Primary */ --color-primary-50: #e3f2fd; --color-primary-500: #1976d2; --color-primary-700: #1565c0; /* Semantic */ --color-success: #2e7d32; --color-warning: #ef6c00; --color-danger: #c62828; /* Surface (Light/Dark 自動切替) */ --surface-bg: light-dark(#fff, #1f2937); --surface-text: light-dark(#333, #e5e7eb); /* Spacing Scale */ --space-xs: 4px; --space-sm: 8px; --space-md: 16px; --space-lg: 24px; --space-xl: 32px; }

現状の問題

  • 色値 #1976d2 が50箇所以上にハードコード
  • ダークモード切替に50+セレクタの上書き
  • spacing が 8px / 12px / 16px / 24px と不統一
  • font-size が 11px〜36px まで15種以上
  • border-radius が 4px / 6px / 8px / 12px と混在

改善効果

  • ダークモードが CSS 変数切替のみで実現
  • ブランド変更がトークン1箇所の修正で完了
  • 一貫した視覚的リズムとスペーシング
  • コンポーネント間のデザイン不整合を根絶
