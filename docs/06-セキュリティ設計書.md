## 1. 概要

本設計書では、ITSM Management / Service Desk のセキュリティ設計を定義する。

**現行実装済み**:

- パスワードのbcryptハッシュ化保存

- OAuth2 Password Flow
- RBAC（viewer < operator < manager < admin）による認可
- 監査ログ（操作前後スナップショット）

- CSP / HSTS セキュリティヘッダー

- Rate Limiting（slowapi）
- Refresh Token 実装
- エラーレスポンス統一

## 2. 認証設計

### 2.1 認証フロー

```
クライアント                    バックエンド
    │   POST /api/auth/login      │
    │  (username + password)      │
    │────────────────────────────▶│  1. bcrypt.checkpw でパスワード検証
    │                             │  2. JWT発行 (exp, sub=user_id)
    │◀────────────────────────────│  200: {access_token, token_type}
    │
    │   GET /api/incidents        │
    │  Authorization: Bearer <jwt>│
    │────────────────────────────▶│  3. get_current_user でトークン検証
    │                             │     - JWTデコード (sub → user_id)
    │                             │     - ユーザー存在・is_active 確認
    │◀────────────────────────────│  4. ロールチェック (require_role)
```

### 2.2 パスワード管理

| 項目 | 仕様 |
|------|------|
| ハッシュ化 | bcrypt（`bcrypt.hashpw` + `bcrypt.gensalt()`） |
| 検証 | `bcrypt.checkpw` |
| 平文保存 | 禁止 |
| 初期パスワード | 初回ログイン時の変更を推奨（Phase 3） |
| パスワードポリシー | 8文字以上・英数字混在（Phase 2実装） |

### 2.3 JWT仕様

| 項目 | 仕様 |
|------|------|
| ライブラリ | python-jose |
| アルゴリズム | `settings.algorithm`（HS256 推奨） |
| ペイロード | `exp`（有効期限）+ `sub`（ユーザーID文字列） |
| 有効期限 | `settings.access_token_expire_minutes`（デフォルト例: 30分） |
| シークレット | `settings.secret_key`（環境変数から注入、デフォルト値禁止） |
| 保存場所（クライアント） | localStorage（現行）。Phase 2で httpOnly Cookie を検討 |

### 2.4 Refresh Token（Phase 1）

| 項目 | 仕様 |
|------|------|
| 目的 | アクセストークン失効後の再発行 |
| 保存 | サーバ側DB（またはSigned Cookie）で管理 |
| ローテーション | リフレッシュ毎に新トークン発行・旧トークン失効 |
| 失効 | ログアウト・パスワード変更時に全トークン失効 |

## 3. 認可（RBAC）

### 3.1 ロール階層

```python
role_order = ["viewer", "operator", "manager", "admin"]
```

### 3.2 ロール別権限マトリクス

| 機能 | viewer | operator | manager | admin |
|------|:------:|:--------:|:-------:|:-----:|
| 画面閲覧（全モジュール） | ✅ | ✅ | ✅ | ✅ |
| インシデント登録・更新・削除 | — | ✅ | ✅ | ✅ |
| 問題・変更・CMDB・資産等のCRUD | — | ✅ | ✅ | ✅ |
| 変更承認 | — | — | ✅ | ✅ |
| 監査ログ参照 | — | — | ✅ | ✅ |
| ユーザー管理 | — | — | — | ✅ |
| システム設定変更 | — | — | ✅ | ✅ |

### 3.3 実装方式

```python
# 参照系: 認証のみ
def list_incidents(..., current_user: User = Depends(get_current_user))

# 書込系: ロール必須
def create_incident(..., current_user: User = Depends(require_role("operator")))
```

## 4. 監査ログ

### 4.1 対象操作

| 操作 | 記録内容 |
|------|----------|
| create | after スナップショット |
| update | before + after スナップショット |
| delete | before スナップショット |

### 4.2 記録項目

| 項目 | 内容 |
|------|------|
| entity_type / entity_id | 操作対象の識別 |
| action | create / update / delete |
| before_json / after_json | カラム値のJSON文字列化 |
| user_id | 操作者 |
| ip_address | 操作元IP |

### 4.3 監査ログの保護

- 削除・更新を禁止（追記専用）
- 参照は admin / manager のみ
- 長期保存（バックアップ対象）

## 5. 通信セキュリティ

### 5.1 CORS

```python
# 現行: settings.cors_origins_list から許可リストを設定
app.add_middleware(
    CORSMiddleware,
    allow_origins=cfg.cors_origins_list,
    allow_credentials=True,
    allow_methods=["*"],
    allow_headers=["*"],
)
```

**Phase 1 改善**: 許可オリジンを本番ドメインに限定（ワイルドカード禁止）。クレデンシャル送信時はオリジン明示必須。

### 5.2 セキュリティヘッダー（Phase 1）

| ヘッダー | 設定例 |
|----------|--------|
| Content-Security-Policy | `default-src 'self'; script-src 'self'` |
| Strict-Transport-Security | `max-age=31536000; includeSubDomains` |
| X-Content-Type-Options | `nosniff` |
| X-Frame-Options | `DENY`（またはSAMEORIGIN） |
| Referrer-Policy | `strict-origin-when-cross-origin` |

### 5.3 HTTPS

- 本番環境ではTLS必須（HSTS有効）
- 開発環境（HTTP localhost）は許容

## 6. アプリケーションセキュリティ

### 6.1 Rate Limiting（Phase 1）

| 対象 | 方針 |
|------|------|
| ログイン | IP/ユーザー単位の試行回数制限（例: 10回/15分） |
| API全般 | ユーザー単位のリクエスト制限（slowapi） |
| 過剰応答 | 429 Too Many Requests |

### 6.2 入力バリデーション

- Pydanticスキーマによる型・値域検証（`Literal` によるenum制約）
- インジェクション対策: SQLAlchemyのパラメータバインド（文字列連結SQL禁止）
- XSS対策: Reactのエスケープ＋CSP。`dangerouslySetInnerHTML` 禁止

### 6.3 セッション・トークン管理

- アクセストークン: 短命（30分程度）
- ログアウト: クライアントでトークン破棄＋サーバ側リフレッシュトークン失効
- パスワード変更: 全セッション無効化

## 7. データセキュリティ

| 項目 | 仕様 |
|------|------|
| パスワード | bcryptハッシュのみ保存 |
| 個人情報 | メールアドレス等は最小限の収集。アクセスログと分離 |
| バックアップ | 暗号化バックアップ（Phase 3） |
| 保存データ | 監査ログは改ざん防止（DB権限分離・追記専用） |

## 8. フロントエンドのセキュリティ（Phase 2）

| 項目 | 内容 |
|------|------|
| CDN依存排除 | React/Babelをunpkg CDNから取得→npmパッケージ化（SRI付きは現行で対応済みだが、バンドルで自己完結化） |
| CSP | Viteビルドで `default-src 'self'` を適用 |
| トークン管理 | localStorage → httpOnly Cookie / メモリ保持を検討 |
| 依存関係 | npm audit 定期実行・脆弱性対応 |

| No | テスト項目 | 確認内容 |
