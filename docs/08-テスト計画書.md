## 1. 概要

本計画書では、ITSM Management / Service Desk の品質保証に関するテスト戦略・テスト項目・受け入れ基準を定義する。

**現状の課題**（`ITSM-WebUI-Evaluation.html` より）:

- テスト充実度スコア: 60/100
- Phase 2 目標: テストカバレッジ 80%
- Phase 3 目標: Playwright E2E テスト充実

---

## 2. テスト戦略（テストピラミッド）

```
        ▲  E2Eテスト（Playwright）
        │   主要シナリオ: ログイン→起票→解決→クローズ
       ╱│╲
      / │ \   統合テスト（pytest + TestClient / DB）
     /  │  \   API・サービス・DB連携
    /   │   \
   /────│────\  単体テスト（pytest / Vitest）
  単体が最も多い構成
```

| 層 | ツール | 対象 | 目標カバレッジ |
|----|--------|------|----------------|
| 単体 | pytest / Vitest | サービス層・ユーティリティ・コンポーネント | 80% |
| 統合 | pytest + FastAPI TestClient | APIエンドポイント・DB操作・認証 | 主要API全件 |
| E2E | Playwright | ユーザー操作シナリオ | 主要フロー |

---

## 3. テスト環境

| 環境 | 用途 | 構成 |
|------|------|------|

## 6. E2Eテスト（Playwright）

### 6.1 主要シナリオ

| No | シナリオ | 手順 | 期待結果 |
|----|----------|------|----------|
| E-01 | ログイン→ダッシュボード表示 | ログイン→ダッシュボード遷移 | KPI 5枚・グラフが表示される |
| E-02 | インシデント作成フロー | 新規作成→フォーム入力→保存 | 一覧に追加されトースト表示 |
| E-03 | インシデント編集 | 行の編集→変更→保存 | 値が反映される |
| E-04 | インシデント削除 | 削除→確認ダイアログ→実行 | 一覧から消える |
| E-05 | 検索・フィルタ | キーワード入力→フィルタ選択 | 該当行のみ表示 |
| E-06 | ソート・ページング | カラムクリック→ページ送り | 順序・ページが正しい |
| E-07 | ダークモード切替 | ヘッダーのトグル | テーマ切替・localStorage保存 |
| E-08 | 全モジュール遷移 | サイドバーで全画面遷移 | 各画面が正常表示 |
| E-09 | 権限チェック | viewerで書込操作 | 403/ボタン非表示 |
